# AI Chat API Usage Guide

## Overview

The AI Chat API provides a simple interface for sending a prompt associated with an existing chat session and receiving an AI-generated response.

The API supports:

- Normal non-streaming responses
- Streaming responses
- Chat/session association through `chat_id`
- Prompt-based AI interaction

---

## Base Route

The router uses:

```text
/ai
```

The chat endpoint is:

```text
POST /ai/chat
```

---

# 1. AI Chat

## POST /ai/chat

Sends a prompt to the AI for an existing chat session.

The request identifies the chat using `chat_id`, provides the prompt, and controls whether the response should be streamed using `stream`.

---

## Request Body

```json
{
  "chat_id": 1,
  "prompt": "What is Redis?",
  "stream": false
}
```

### Fields

| Field | Type | Required | Default | Description |
|---|---|---:|---:|---|
| `chat_id` | integer | Yes | — | ID of the chat session |
| `prompt` | string | Yes | — | User prompt sent to the AI |
| `stream` | boolean | No | `false` | Whether to return the response as a stream |

---

# 2. Non-Streaming Request

Set:

```json
"stream": false
```

Example:

```http
POST /ai/chat
Content-Type: application/json
```

```json
{
  "chat_id": 1,
  "prompt": "What is Redis?",
  "stream": false
}
```

## Response

The route waits for the complete result from `ai_call()` and returns:

```json
{
  "text": "Redis is an in-memory data store commonly used for caching and other fast data-access workloads."
}
```

The exact response text depends on the AI service.

---

# 3. Streaming Request

Set:

```json
"stream": true
```

Example:

```http
POST /ai/chat
Content-Type: application/json
```

```json
{
  "chat_id": 1,
  "prompt": "Explain how Redis works.",
  "stream": true
}
```

The route uses:

```python
StreamingResponse(
    ai_call_stream(
        chat_id=request.chat_id,
        prompt=request.prompt,
    ),
    media_type="text/plain",
)
```

Therefore the response is returned using:

```text
Content-Type: text/plain
```

The response is streamed as generated by `ai_call_stream()`.

The exact chunk format and chunk boundaries are determined by the implementation of `ai_call_stream()` and are not defined by this router.

# 4. JavaScript Examples

## Non-Streaming

```javascript
const response = await fetch("http://localhost:8000/ai/chat", {
  method: "POST",
  headers: {
    "Content-Type": "application/json"
  },
  body: JSON.stringify({
    chat_id: 1,
    prompt: "What is Redis?",
    stream: false
  })
});

const data = await response.json();

console.log(data.text);
```

---

## Streaming

```javascript
const response = await fetch("http://localhost:8000/ai/chat", {
  method: "POST",
  headers: {
    "Content-Type": "application/json"
  },
  body: JSON.stringify({
    chat_id: 1,
    prompt: "Explain how Redis works.",
    stream: true
  })
});

const reader = response.body.getReader();
const decoder = new TextDecoder();

while (true) {
  const { value, done } = await reader.read();

  if (done) {
    break;
  }

  const chunk = decoder.decode(value, {
    stream: true
  });

  console.log(chunk);
}
```

---

## Streaming

```python
import requests


response = requests.post(
    "http://localhost:8000/ai/chat",
    json={
        "chat_id": 1,
        "prompt": "Explain how Redis works.",
        "stream": True,
    },
    stream=True,
)

for chunk in response.iter_content(
    chunk_size=None,
    decode_unicode=True,
):
    if chunk:
        print(chunk, end="")
```

# 7. Request Model

The endpoint uses the following request model:

```python
class AIChatRequest(BaseModel):
    chat_id: int
    prompt: str
    stream: bool = False
```

This means:

- `chat_id` must be an integer.
- `prompt` must be a string.
- `stream` is optional.
- If `stream` is omitted, it defaults to `false`.

Example with the default:

```json
{
  "chat_id": 1,
  "prompt": "Hello"
}
```

is equivalent to:

```json
{
  "chat_id": 1,
  "prompt": "Hello",
  "stream": false
}
```

## Streaming

      |

# 9. Important Behavior

### `chat_id`

The endpoint requires an existing chat identifier:

```json
{
  "chat_id": 1
}
```

The router passes this value directly to the AI service.

The router itself does not define chat creation or chat validation logic.

---

### `prompt`

The prompt is passed directly to:

```python
ai_call(
    chat_id=request.chat_id,
    prompt=request.prompt,
)
```

or:

```python
ai_call_stream(
    chat_id=request.chat_id,
    prompt=request.prompt,
)
```

---

### `stream`

The `stream` field controls which service function is used:

```python
if request.stream:
    ...
```

`false` uses `ai_call()`.

`true` uses `ai_call_stream()`.

# 13. Scope of This API

This router is a high-level AI chat interface.

It does not directly expose:

- LLM provider selection
- LLM model selection
- Tool definitions
- Temperature configuration
- Token limits
- Raw provider responses
- Provider-specific chat-completion parameters

Those concerns, if required, are handled by the underlying AI service or the separate LLM Gateway API.

The router only accepts:

```text
chat_id
prompt
stream
```

and delegates the actual AI operation to:

```python
ai_call()
```

or:

```python
ai_call_stream()
```

# 14. Source Route

Current implementation:

```python
from fastapi import APIRouter
from fastapi.responses import StreamingResponse
from pydantic import BaseModel

from SITE_MODULE.ai.builder import ai_call, ai_call_stream


class AIChatRequest(BaseModel):
    chat_id: int
    prompt: str
    stream: bool = False


router = APIRouter(
    prefix="/ai",
    tags=["AI CHAT"],
)


@router.post("/chat")
async def ai_chat(
    request: AIChatRequest,
):
    if request.stream:
        return StreamingResponse(
            ai_call_stream(
                chat_id=request.chat_id,
                prompt=request.prompt,
            ),
            media_type="text/plain",
        )

    response = await ai_call(
        chat_id=request.chat_id,
        prompt=request.prompt,
    )

    return {
        "text": response,
    }
```
